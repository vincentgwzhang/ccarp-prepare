# MCP 架构与使用场景：场景练习

> 清单 #1 · Domain 3: Integration（19%） · 2026-09-07
> 8 道原创练习，非官方真题。结构参考 [Exam_Guide.md](../../../Exam_Guide.md) 第 8 节：明确场景约束、选择最直接解决问题的方案，并解释干扰项。每题标明选择数量。
> 先学习 [knowledge.md](knowledge.md)。答案依据该文件所链接的官方资料；不测试未经验证的 SDK 支持情况，不把最新协议字段当成指南明确要求的背诵内容。

## 1. 多应用复用现有业务系统

### Question

公司有三个支持 MCP 的 AI 应用，都需要查询同一个订单服务。订单 REST API 已稳定运行；团队希望统一能力发现和调用适配，同时保留已有业务规则。哪种设计最符合目标？（选择 1 项）

### Options

- A. 为三个应用分别编写专用工具适配，并让各自团队独立维护订单字段映射。
- B. 把订单数据库完整导出到每个应用的 system prompt，避免调用集成服务。
- C. 在现有订单 API 前提供 MCP server，由三个应用各自的 client 接入，订单规则仍由业务层执行。
- D. 将订单服务改成自主 agent，取消现有确定性的业务校验，由模型判断请求是否合法。

### Correct Answer

C。

### Explanation

C 对准“统一接入与复用”且保留现有业务边界，不要求重写订单系统。A 可以工作，但延续了题目希望减少的重复适配。B 存在更新和数据暴露问题，也无法替代实时查询。D 把协议接入问题扩大成 agent 重构，且错误取消业务校验。选择 MCP 的理由是此处的复用需求，不是它永远优于 API。

## 2. 理解组件职责

### Question

一个内部 Claude 助手同时连接订单 MCP server 和知识库 MCP server。设计评审希望避免把协议接入层误当成模型运行层。哪两项描述正确？（选择 2 项）

### Options

- A. Host 可以管理两个 client，分别与两个 server 通信。
- B. 每个 MCP server 都必须部署一个 Claude 模型，否则不能响应工具调用。
- C. 为了支持上下文共享，两个 server 应默认获得用户的完整会话记录。
- D. Server 可以仅包装业务能力，不包含模型；host 管理模型交互和上下文使用。
- E. 一个远端 MCP server 一旦被一个 client 连接，就不能服务其他用户的 client。

### Correct Answer

A、D。

### Explanation

A、D 正确区分连接组件、宿主与能力提供者。B 把 server 错当成模型服务。C 扩大了数据共享范围；跨来源上下文应由 host 按需管理，不默认全部外发。E 混淆 client 对一个 server 的关系与 server 的并发服务能力。

## 3. 连接机制的硬约束

### Question

团队只需要查询工具，计划使用 Messages API 的远端 MCP connector。现有 server 只能作为内网机器上的 stdio 子进程运行，且安全政策明确禁止公开该 server。团队允许将脱敏后的查询结果发送给 Claude API。哪种调整最合理？（选择 1 项）

### Options

- A. 把内网机器上的文件路径填入远端 connector URL，保持 stdio 不变。
- B. 在内网自建 host/client 调用该 stdio server，再将获准的脱敏结果送入 Claude API 交互流程。
- C. 临时把 server 无认证地暴露公网，完成查询后立即关闭即可满足原政策。
- D. 为 system prompt 增加“允许访问内网文件”，让远端 connector 自动访问内网子进程。

### Correct Answer

B。

### Explanation

B 同时尊重 server 不公开和结果可脱敏外发两个约束。A 的文件路径不是可达的远端 MCP endpoint。C 直接违反题目明确的政策。D 不能用自然语言指令改变网络边界或产品支持范围。这里依据 2026-09-07 官方 connector 文档的远端 HTTP / 不直接支持 stdio 限制，不是说 MCP 协议不能用于本地。

## 4. 工具、资源与产品支持

### Question

团队把只读取消政策以 MCP resource 暴露。经确认，其选定的产品入口只支持 MCP tool calls，不支持 resource 读取。政策需要按需查询，不希望每次把全部内容写入 prompt。哪种改动最直接？（选择 1 项）

### Options

- A. 保持配置不变，仅升级为更强的模型以理解 resource URI。
- B. 把 resource URI 改名为 tool，但不实现任何工具接口。
- C. 把政策复制到 tool 的名称中，避免调用过程。
- D. 在 server 增加受访问控制的只读查询 tool，由该入口调用并返回所需政策内容。

### Correct Answer

D。

### Explanation

D 将所需数据通过当前入口支持的原语提供，而且 tool 并不必须产生写入。A 不能解决入口缺失协议能力的问题。B 的重命名没有实现工具发现和调用契约。C 把内容塞入名称既不等于可调用能力，也不满足合理的按需读取设计。本题不要求所有 resource 都改成 tool；改动由明确的客户端限制驱动。

## 5. 判断是否真的需要 MCP

### Question

一个夜间 Java 批处理只调用一个稳定的内部 REST API，将结果交给 Claude 生成摘要。没有其他消费者，没有动态工具发现需求，也没有现成 MCP server。团队当前的主要目标是减少维护组件。最佳决定是什么？（选择 1 项）

### Options

- A. 暂时保留直接 API 集成；出现跨应用复用或其他明确需求时再评估 MCP。
- B. 必须先增加 MCP server，否则 Claude 无法使用任何外部 API 数据。
- C. 将 REST、MCP、CLI 三种接口全部实现，才能证明系统具备架构弹性。
- D. 增加 MCP server，因为使用 MCP 必然减少每次模型推理的 token 数。

### Correct Answer

A。

### Explanation

A 根据当前约束选择足够简单的方案。B 错误地把 MCP 当成模型获取外部数据的唯一途径。C 增加题目没有要求的维护面。D 没有必然性：协议接入不等于 prompt/context 优化。可复用性是潜在收益，必须与实际需求比较，不能脱离场景。

## 6. 连接成功不代表授权正确

### Question

一个 MCP server 成功验证了用户令牌，但 `get_order_status` 只按模型提供的 `order_id` 查询数据库。测试发现用户能读取其他租户订单。团队还发现普通客服的工具配置包含从不需要的删除账号操作。哪两项最直接修复这些已知缺口？（选择 2 项）

### Options

- A. 在 system prompt 加入“请不要读取其他租户订单”，保持查询代码不变。
- B. 给所有查询增加审计日志，把跨租户访问留给事后调查。
- C. 在 server/业务层按可信用户身份和租户检查订单访问权限，不信任模型参数提供授权依据。
- D. 从普通客服的可用配置移除不需要的删除账号能力。
- E. 改用更大的模型，保留当前查询逻辑和所有工具。

### Correct Answer

C、D。

### Explanation

C 修复对象级授权缺失；D 消除角色不需要的能力，延续 Guide Sample 1 的最小权限判断逻辑。A 是行为提醒，不能替代授权。B 有审计价值，但不能阻止已知越权。E 不改变权限边界。今天只在 MCP 集成场景下识别责任，不代表已完成完整的 Auth/Authz 学习项。

## 7. 业务失败被误报为成功

### Question

助手通过 MCP 创建一条业务记录。网络请求返回成功，但工具结果明确携带 `isError: true`，说明业务校验失败。Host 丢弃该字段，只把“请求已送达”交给模型，最终助手告诉用户“创建成功”。最应先修改哪里？（选择 1 项）

### Options

- A. 增加 HTTP 超时时间，确保网络请求能等待更久。
- B. 修复 host 的结果处理，让业务失败信息作为对应工具结果进入模型流程，并禁止将送达等同成功。
- C. 把温度设置得更低，保持结果处理逻辑不变。
- D. 对同一请求无限重试，直到模型生成肯定答案。

### Correct Answer

B。

### Explanation

证据指向 host 错误转换结果，而不是网络超时或模型随机性。B 恢复了业务结果的含义。A 无法修复已返回但被丢弃的信息。C 不会让模型看到未传入的错误。D 既不解决校验原因，还可能增加副作用风险。协议/传输成功与业务执行成功是不同层次。

## 8. 升级后尚未到达工具调用就失败

### Question

一次升级只更换了 MCP client。订单 API、模型和工具定义都未变；故障发生在任何 `tools/call` 之前。旧 server 的文档要求先 `initialize`，新 client 的默认实现使用每请求元数据与 `server/discover`。第一步最应做什么？（选择 1 项）

### Options

- A. 优化工具描述，让模型更容易选中订单查询工具。
- B. 扩大上下文窗口，让模型记住更多连接日志。
- C. 检查双方支持的协议版本及兼容模式，建立共同支持的通信流程后再验证工具调用。
- D. 将所有订单操作改成 prompt 模板，跳过协议兼容性检查。

### Correct Answer

C。

### Explanation

故障位置与唯一变更指向协议兼容性，C 最直接。A、B 针对模型阶段，但此时工具调用尚未开始。D 混淆能力原语与连接基础，也不能修复不兼容。本题已提供版本行为作为条件，测试架构排障逻辑，不要求背诵日期或假设某个 SDK 自动降级。
