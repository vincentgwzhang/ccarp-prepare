# Capability bloat 与最小权限：练习

> 学习序号 04 · 清单 #4 · Domain 3（19%） · 2026-09-10
> 7 道原创场景题，非官方真题。题型和 rationale 参考 [Exam_Guide.md](../../../Exam_Guide.md) 第 8 节；事实依据与核查链接见 [knowledge.md](knowledge.md)。

## 1. 草稿助手的工具集

### Question

法务团队部署一个 agent，只负责读取已分配的合同并生成修改建议草稿。当前工具还允许签署合同、向外部收件人发送邮件和删除合同。哪项改变最符合最小权限并最直接降低风险？（选择 1 项）

### Options

- A. 保留所有工具，对签署、发送和删除调用增加日志。
- B. 移除签署、发送和删除工具，只保留读取与草稿能力。
- C. 保留所有工具，在 system prompt 中强调“绝不执行高风险动作”。
- D. 换用更强模型，以降低误选工具的概率。

### Correct Answer

B。

### Explanation

B 直接消除该角色不需要的能力面，与 Guide Sample 1 的判断逻辑相同。A 有助于事后审计，但第一次危险操作仍可发生。C 是行为引导，不是执行层权限边界。D 可能改变决策质量，却不会收窄工具或后端权限。

## 2. 偶发退款需求

### Question

客服 agent 处理大量查询，其中不到 1% 需要退款。退款必须验证订单归属、额度和审批人，而普通会话只需查订单。哪种架构最佳？（选择 1 项）

### Options

- A. 所有客服会话都使用同时具备查询和无限额退款权限的共享凭证。
- B. 从普通 agent 移除退款工具；识别退款意图后路由到专用流程，由该流程重新校验身份、订单、额度和审批。
- C. 保留退款工具，但把 temperature 调低到 0。
- D. 保留退款工具，只在调用后检查日志中是否存在异常。

### Correct Answer

B。

### Explanation

B 将少见的高影响能力隔离到专用边界，并在执行前实施确定性验证。A 扩大每个会话的 blast radius。C 不是授权控制，也不能保证没有错误或攻击。D 是事后侦测，无法替代调用前的最小权限与审批。

## 3. 只读订单工具的隐藏风险

### Question

一个工具名为 `read_order`，schema 只接收 `order_id`。handler 使用跨租户数据库管理员凭证，并把模型提供的订单号直接拼入查询。哪两项是最重要的修复？（选择 2 项）

### Options

- A. 使用参数化的固定只读查询，并在后端验证当前主体可访问该订单。
- B. 将执行凭证缩小到所需数据和只读操作，避免共享管理员身份。
- C. 把工具描述改成“安全地读取订单”，其余不变。
- D. 记录每个订单号，因此无需在执行前检查权限。
- E. 增大 context window，让 Claude记住全部租户规则。

### Correct Answer

A、B。

### Explanation

A 同时处理输入安全与 object-level authorization；B 缩小底层执行身份的权限和潜在影响范围。C 只改善模型理解，不强制安全边界。D 是审计而非预防。E 把确定性访问控制错误地交给模型上下文，而且不会限制数据库凭证。

## 4. Schema 合法不等于调用获准

### Question

团队启用了 strict tool use，所有 `transfer_funds` 调用都符合 JSON Schema。一次调用结构完全合法，但付款人不拥有源账户。系统应如何处理？（选择 1 项）

### Options

- A. 执行转账，因为 schema conformance 已证明请求安全。
- B. 让 Claude 再次输出同一参数，只要两次一致就执行。
- C. 在模型之外验证已认证主体、源账户授权和业务策略；未获授权则拒绝。
- D. 把调用写入日志后执行，以便未来审计。

### Correct Answer

C。

### Explanation

C 区分了参数结构验证与业务授权。Strict schema 可以保证字段形状，却不能证明账户归属或转账许可。A 混淆结构正确和语义获准。B 的一致性不是权限证据。D 仍会先造成未经授权的副作用。

## 5. 不可信网页与通用 Bash

### Question

一个研究 agent 会读取任意网页。它同时拥有未隔离的通用 Bash、生产凭证和开放网络出口，但任务只需要检索网页并撰写摘要。哪三项最直接降低 prompt injection 的可利用影响？（选择 3 项）

### Options

- A. 移除任务不需要的通用 Bash 和生产凭证。
- B. 将执行环境隔离，并把网络出口限制到批准的目标。
- C. 把网页中的所有指令都标成“大写不可信”，同时保留全部权限。
- D. 只提供完成检索与摘要所需的窄工具，并在运行时强制其边界。
- E. 采用更大的模型，因此不再需要权限控制。

### Correct Answer

A、B、D。

### Explanation

A 消除无关高影响能力，B 限制即使发生误调用时的 blast radius，D 将能力收敛到业务所需且由运行时强制。C 可以作为内容标记或提示信号，但保留全部权限时不是可靠边界。E 把安全控制错误地替换成模型能力。

## 6. 审批疲劳

### Question

一个内部 agent 每次只读知识库查询都要求人工确认，同时极少发生的客户数据导出也使用同样的确认弹窗。员工开始不看详情就批准。最佳改进是什么？（选择 1 项）

### Options

- A. 删除所有确认，让 agent 自动执行全部动作。
- B. 保留统一弹窗，但要求员工签署培训声明。
- C. 对受范围限制的低风险读取预先允许；将数据导出隔离为高风险能力，展示目标和影响并要求针对性审批。
- D. 增加更多普通读取确认，让员工形成习惯。

### Correct Answer

C。

### Explanation

C 根据风险分层，减少无意义提示，同时为高影响动作保留清晰的 step-up gate。A 对导出能力过度放权。B 没有修复界面与控制设计。D 会加剧 approval fatigue，使人工确认更像机械点击。

## 7. Capability bloat 评审

### Question

架构委员会审查一个采购 agent。以下哪三项证据最能证明其能力配置符合最小权限？（选择 3 项）

### Options

- A. 每个工具都映射到明确的角色任务，不需要的工具未暴露。
- B. 必需工具的资源、操作、参数和凭证范围有执行层限制。
- C. 高影响动作有确定性策略校验和适当审批，并记录授权决策。
- D. Agent 使用当前最强的 Claude 模型。
- E. System prompt 很长，包含“始终安全”十次。

### Correct Answer

A、B、C。

### Explanation

A 证明工具集合必要，B 证明保留能力被收窄，C 证明敏感副作用有执行前 gate 和可审计证据；三者构成分层控制。D 与权限范围没有直接关系。E 只能影响模型行为，不能作为强制授权机制，也不能弥补不必要的工具暴露。
