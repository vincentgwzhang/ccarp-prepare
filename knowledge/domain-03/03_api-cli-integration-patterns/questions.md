# API/CLI 集成模式对比：练习

## 1. 在线服务选型

### Question

一个已有身份验证和 HTTP 客户端基础设施的 Java 多租户服务，需要把每条工单分类为固定类别。它不需要仓库操作或多步代理工作，团队希望尽量减少新增运行组件。哪项方案最合适？（选择 1 项）

### Options

- A. 每个请求启动 Claude Code 进程，让其自行发现本地工具，再决定怎样分类。
- B. 使用 API/SDK，把响应验证、身份隔离和请求预算纳入已有服务。
- C. 因为 CLI 可以返回 JSON，所以必须使用 CLI 才能验证结果。
- D. 将工单发送给三个 agent 投票，以替代身份验证。

### Correct Answer

B。

### Explanation

B 符合简单模型任务与已有基础设施，避免增加没有收益依据的进程和代理管理。A 可以被设计成可运行系统，但不符合减少组件的目标。C 把结构化输出错误地视为 CLI 独有。D 增加成本，且投票与租户身份无关。

## 2. 工具调用停在模型输出

### Question

Claude 返回订单查询的 client `tool_use`。应用把该块当作最终答案发给用户，用户没有收到实际订单状态。最直接的修复是什么？（选择 1 项）

### Options

- A. 调整提示词，要求 Claude 更自信地回答订单状态。
- B. 将工具名改为更长的自然语言描述，然后仍直接返回该块。
- C. 校验并执行订单查询，保留 assistant 调用消息，以关联该调用 ID 的 `tool_result` 回传给 Claude。
- D. 只等待更久，所有 client tools 都会由 Claude API 自动执行。

### Correct Answer

C。

### Explanation

C 补齐缺失的应用执行与结果回传环节。A、B 没有取得实时数据。D 混淆 client tools 与服务端执行的工具。模型提出调用不代表业务操作已经运行。

## 3. 成熟 CLI 的安全包装

### Question

企业旧系统没有 API，但有稳定的只读查询 CLI。参数来源包含用户输入。团队决定在受控 worker 内包装它。哪两项设计最直接提高可靠性与安全性？（选择 2 项）

### Options

- A. 固定可执行程序和子命令，校验参数后通过独立参数数组传入。
- B. 让模型构造完整 shell 命令，以适应所有未来需求。
- C. 并发消费并限制 stdout/stderr，设置超时，检查退出状态和结构化业务结果。
- D. 只要进程启动成功就向模型报告业务成功。
- E. 给 worker 管理员权限，以减少权限错误带来的重试。

### Correct Answer

A、C。

### Explanation

A 缩小命令执行范围并避免 shell 解释用户文本，仍需业务授权。C 防止进程挂起和输出失控，并区分启动与完成。B 扩大命令注入与任意操作风险。D 缺少执行证据。E 与只读查询的实际权限需求不符。

## 4. CI 结果解析

### Question

团队已有获准的 Claude Code CI 环境，用于多步仓库检查。升级后，脚本从终端最后一行提取答案的逻辑失效。进程执行本身没有失败。最佳修改是什么？（选择 1 项）

### Options

- A. 继续截取最后一行，仅要求模型“永远不输出解释”。
- B. 每次执行都改为交互模式，让开发者复制结果。
- C. 立即迁移到多个协作 agent，因为解析失败代表模型能力不足。
- D. 使用文档支持的机器输出模式，解析约定字段并验证结果结构，管理 CLI 版本兼容性。

### Correct Answer

D。

### Explanation

D 对准不稳定的人类可读输出契约。A 的提示不保证外层终端输出格式。B 牺牲已有自动化需求。C 没有解决解析根因。即使成功解析 JSON，也还需检查业务结果。

## 5. API 权限错误

### Question

服务在更换运行身份后，访问某资源稳定返回 403。请求结构没变。团队提出增加模型能力、无限重试或审查授权三种方向。最应先做什么？（选择 1 项）

### Options

- A. 增大输出 token 预算，让模型生成更完整的请求理由。
- B. 核对新身份对目标资源的访问权限，按所需最小范围修正授权。
- C. 每秒重试，直到服务端允许该身份。
- D. 把同一调用改成 CLI，确保绕过底层 API 授权。

### Correct Answer

B。

### Explanation

时间关联与错误类型均指向授权。A 与权限无关。C 通常不能恢复稳定的授权缺失，还增加负载。D 错误假设接口形式改变会取消服务端授权；CLI 也可能调用相同 API。

## 6. 重试的范围

### Question

一个流程先调用模型生成付款参数，再调用支付服务，最后生成说明。支付服务超时，调用方尚不清楚是否已扣款。哪两项最适合纳入恢复方案？（选择 2 项）

### Options

- A. 用全新业务 ID 重新执行整个流程，因为超时证明没有扣款。
- B. 凭模型生成的“已完成”文字判断付款结果。
- C. 根据原业务 ID 查询付款状态，并在允许重试时保持业务幂等语义。
- D. 检查 SDK、应用和队列的重试是否叠加，为完整流程设置有界预算。
- E. 改用 CLI 后删除幂等逻辑，因为退出码能保证付款仅执行一次。

### Correct Answer

C、D。

### Explanation

C 处理不确定执行结果，D 限制重试放大。A 可能重复扣款。B 没有真实执行证据。E 把退出状态误当 exactly-once 保证；API 和 CLI 都需要管理副作用。这是业务系统恢复设计，不依赖某个 SDK 已自动提供幂等性。
